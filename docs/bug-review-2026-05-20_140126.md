## 1. Saving Leaves The App Dirty

Severity: High

Files:

- `src/app.rs:29`
- `src/app.rs:37`
- `src/project/io.rs:6`

Before state:

- `is_dirty()` serializes the live tree with `serde_json::to_string`, which produces compact JSON.
- `do_save()` stores the return value from `project::io::save()`.
- `project::io::save()` returns `serde_json::to_string_pretty(tree)`.
- Result: after Save, the clean snapshot is pretty JSON but future dirty checks compare against compact JSON, so saved projects can still show `*` as dirty immediately after saving.

Fix proposal:

- Use one canonical serialization form for both saved snapshots and dirty checks.
- Prefer moving a `to_project_json(tree)` helper into `src/project/io.rs` so app code does not duplicate the serialization choice.

After state:

```rust
// project/io.rs
pub fn serialize(tree: &UiTree) -> Result<String, String> {
    serde_json::to_string_pretty(tree).map_err(|e| format!("Serialize error: {e}"))
}

pub fn save(path: &Path, tree: &UiTree) -> Result<String, String> {
    let json = serialize(tree)?;
    std::fs::write(path, &json).map_err(|e| format!("Write error: {e}"))?;
    Ok(json)
}

// app.rs
fn is_dirty(&self) -> bool {
    let current = crate::project::io::serialize(&self.ui_tree).unwrap_or_default();
    self.saved_json.as_ref().map_or(!self.ui_tree.widgets.is_empty(), |snap| current != *snap)
}
```

## 2. New/Open Can Silently Discard Unsaved Work

Severity: High

Files:

- `src/app.rs:50`
- `src/app.rs:58`
- `src/app.rs:127`
- `src/app.rs:166`

Before state:

- Dirty tracking exists and is shown in the title/menu.
- `cmd_new()` immediately replaces `ui_tree`.
- `cmd_open()` immediately loads a selected file and replaces `ui_tree`.
- Result: Ctrl+N, File > New, Ctrl+O, or File > Open can destroy unsaved canvas edits without prompting.

Fix proposal:

- Gate destructive commands through a confirmation path when `is_dirty()` is true.
- If a full modal is not ready, defer the requested command into a `PendingCommand` enum and render a small egui confirmation window.

After state:

```rust
enum PendingCommand {
    New,
    Open,
}

fn request_destructive_command(&mut self, command: PendingCommand) {
    if self.is_dirty() {
        self.pending_command = Some(command);
    } else {
        self.run_command(command);
    }
}
```

Expected behavior after fix:

- Clean project: New/Open runs immediately.
- Dirty project: user sees Save / Discard / Cancel before the tree is replaced.

## 3. Codegen Emits Invalid Rust For Ordinary Labels And Bindings

Severity: High

Files:

- `src/codegen/egui_emitter.rs:14`
- `src/codegen/egui_emitter.rs:24`
- `src/codegen/state_emitter.rs:15`
- `src/panels/properties.rs:25`

Before state:

- Labels are interpolated directly into Rust string literals.
- State bindings are interpolated directly into field names.
- The properties panel accepts any binding string.
- Result: normal user input can break generated code. Examples:

```text
Label: He said "go"
Generated: ui.button("He said "go"")

Binding: user-name
Generated: user-name: String,
Generated: self.user-name
```

Fix proposal:

- Keep raw labels in `UiTree`, but escape labels at codegen time with a Rust string literal helper.
- Validate or normalize state bindings before storing them, or emit through a validated identifier type.
- Surface invalid binding feedback in the properties panel instead of generating broken code.

After state:

```rust
fn rust_string_literal(value: &str) -> String {
    format!("{value:?}")
}

fn valid_binding(value: &str) -> Option<&str> {
    // ASCII MVP: [A-Za-z_][A-Za-z0-9_]*
    // Reject Rust keywords or append `_field`.
}

format!("    if ui.button({}).clicked() {{ }}\n", rust_string_literal(&w.props.label));
```

Expected behavior after fix:

- Labels with quotes, backslashes, or newlines still generate valid Rust.
- Invalid bindings are rejected or normalized before they reach `state_emitter`.

## 4. Duplicate State Bindings Generate Duplicate Struct Fields

Severity: Medium-High

Files:

- `src/widgets/label.rs`
- `src/widgets/text_input.rs`
- `src/widgets/slider.rs`
- `src/widgets/mod.rs:18`
- `src/codegen/state_emitter.rs:7`

Before state:

- Every new Label defaults to `label_text`.
- Every new TextInput defaults to `text_field`.
- Every new Slider defaults to `slider_value`.
- Every new Checkbox defaults to `is_enabled`.
- `state_emitter` emits one field per widget binding with no dedupe.
- Result: adding two TextInputs creates invalid generated state:

```rust
struct AppState {
    text_field: String,
    text_field: String,
}
```

Fix proposal:

- Generate unique default bindings when widgets are added to `UiTree`.
- Also make `state_emitter` dedupe bindings as a defensive backstop.

After state:

```rust
// On add:
text_field
text_field_2
text_field_3

// Defensive state emitter behavior:
let mut seen = BTreeMap::<String, &'static str>::new();
```

Expected behavior after fix:

- Multiple widgets of the same kind produce unique AppState fields.
- If a user manually duplicates a binding, the properties panel warns and codegen remains deterministic.

## 5. Canvas And Codegen Do Not Represent The Same Layout

Severity: High, architecture risk

Files:

- `src/canvas/interaction.rs:204`
- `src/canvas/widget_instance.rs:4`
- `src/codegen/egui_emitter.rs:5`

Before state:

- Canvas renders widgets from `WidgetInstance.rect`.
- Move/resize/property edits mutate `rect`.
- `egui_emitter` ignores `rect` entirely and emits a vertical `CentralPanel` flow.
- Result: the user can position and resize widgets on the canvas, but generated Rust does not reproduce that canvas. This violates the "zero gap between canvas and code" project principle even though both views read `UiTree`.

Fix proposal:

- Keep codegen in `src/codegen/`, but emit egui layout primitives that reflect `rect`.
- For the current absolute-position MVP, use an `egui::Area` or `ui.allocate_ui_at_rect` strategy per widget.
- Preserve widget size for controls where egui supports it.

After state:

```rust
egui::Area::new(egui::Id::new("widget_<id>"))
    .fixed_pos(egui::pos2(x, y))
    .show(ctx, |ui| {
        ui.set_min_size(egui::vec2(w, h));
        ui.button("Button");
    });
```

Expected behavior after fix:

- Moving/resizing a canvas widget changes the generated Rust layout.
- The code panel and canvas remain two live projections of the same `UiTree` data.

## 6. Properties Panel Can Create Invalid Rects And Slider Ranges

Severity: Medium

Files:

- `src/panels/properties.rs:42`
- `src/panels/properties.rs:48`
- `src/canvas/interaction.rs:6`
- `src/canvas/widget_instance.rs:4`

Before state:

- Drag resizing enforces `MIN_SIZE`, but property edits do not.
- `W` and `H` can be set to zero or negative values.
- Slider `Min` can be set greater than `Max`.
- Result: widgets may disappear, hit testing becomes strange, and generated sliders can be nonsensical.

Fix proposal:

- Centralize widget validation on `UiTree` mutation or in `WidgetInstance` helpers.
- Clamp dimensions to the same `MIN_SIZE` used by canvas interaction.
- Normalize slider min/max or reject invalid ranges in the properties panel.

After state:

```rust
w.rect.w = w.rect.w.max(MIN_SIZE);
w.rect.h = w.rect.h.max(MIN_SIZE);
if w.props.min > w.props.max {
    std::mem::swap(&mut w.props.min, &mut w.props.max);
}
```

Expected behavior after fix:

- Canvas, properties, save/load, and codegen all see valid widget geometry.
- Slider codegen always receives a valid range.

## 7. Loaded Project Schema Has No Guardrails

Severity: Medium

Files:

- `src/project/io.rs:15`
- `src/project/schema.rs`
- `src/project/ui_tree.rs`

Before state:

- `load()` deserializes JSON directly into `UiTree`.
- There is no schema version, migration hook, or post-load validation.
- Result: hand-edited or older `.rohkai.json` files can introduce invalid rects, duplicate IDs, duplicate bindings, or future incompatible shape changes.

Fix proposal:

- Add a project envelope with a schema version before the file format spreads.
- Run `tree.validate_and_repair()` after deserialization.

After state:

```rust
#[derive(Serialize, Deserialize)]
struct ProjectFile {
    schema_version: u32,
    tree: UiTree,
}

pub fn load(path: &Path) -> Result<UiTree, String> {
    let mut project: ProjectFile = serde_json::from_str(&json)?;
    project.tree.validate_and_repair();
    Ok(project.tree)
}
```

Expected behavior after fix:

- Future Stage 4+ project files have a migration path.
- Invalid loaded data is repaired or rejected before reaching canvas/codegen.
