## 2. Saving Still Leaves The App Dirty

Severity: High

Files:

- `src/app.rs:47`
- `src/app.rs:55`
- `src/project/io.rs:6`

Before state:

- `is_dirty()` serializes the tree with compact `serde_json::to_string`.
- `project::io::save()` serializes with `serde_json::to_string_pretty`.
- `do_save()` stores the pretty JSON as `saved_json`.
- Result: after saving, the next dirty check compares compact JSON to pretty JSON and can immediately show the project as dirty.

Fix proposal:

- Centralize serialization in `project::io` and use the same function for save, open snapshots, and dirty checks.

After state:

```rust
pub fn serialize(tree: &UiTree) -> Result<String, String> {
    serde_json::to_string_pretty(tree).map_err(|e| format!("Serialize error: {e}"))
}

fn is_dirty(&self) -> bool {
    let current = crate::project::io::serialize(&self.ui_tree).unwrap_or_default();
    self.saved_json
        .as_ref()
        .map_or(!self.ui_tree.widgets.is_empty(), |snap| current != *snap)
}
```

Expected behavior after fix:

- Save clears the dirty indicator.
- Opened files use the same clean snapshot format as saved files.

## 4. Grid Snap Step Can Freeze The Canvas

Severity: High

Files:

- `src/app.rs:383`
- `src/canvas/interaction.rs:32`
- `src/canvas/interaction.rs:431`

Before state:

- The snap step `DragValue` has no lower bound.
- If the user sets `snap_step` to `0` or a negative number and snap is enabled:
  - `snap(val, step)` divides by zero or produces invalid values.
  - Grid drawing uses `x += step` and `y += step`; with `step <= 0`, the while loops can never progress.
- Result: the UI can hang hard from a normal property/ribbon edit.

Fix proposal:

- Clamp `snap_step` at the UI boundary and before every use.
- Prefer a named minimum such as `MIN_SNAP_STEP: f32 = 1.0`.

After state:

```rust
ui.add(
    egui::DragValue::new(&mut self.canvas_settings.snap_step)
        .speed(0.5)
        .range(1.0..=256.0)
        .suffix("px"),
);

let step = settings.snap_step.max(1.0);
```

Expected behavior after fix:

- Snap math always has a positive divisor.
- Grid rendering cannot enter an infinite loop because of user-edited snap settings.

## 5. Template Click Can Drop The Template Instead Of Instantiating It

Severity: High

Files:

- `src/panels/templates.rs:91`
- `src/canvas/interaction.rs:555`
- `src/app.rs:421`

Before state:

- Template panel click writes loaded instances into `interaction.template_drag`.
- Canvas handler consumes `state.template_drag.take()` on `primary_released`.
- On a template panel click, the pointer is still in the left panel, not inside the canvas, so `resp.rect.contains(pos)` is false.
- The template instances have already been taken, so the app-level center-placement fallback at `src/app.rs:421` never sees them.
- Result: "Click to add" can silently do nothing.

Fix proposal:

- Separate template click-add from template drag-drop state.
- Use `RohKaiApp::template_drag_pending` or a new `template_click_pending` for click-to-center.
- Only consume drag state in canvas when the pointer is released over the canvas; otherwise preserve or cancel explicitly.

After state:

```rust
// templates panel click
*template_click_pending = Some(instances);

// app post-panel, before or after canvas
if let Some(instances) = self.template_click_pending.take() {
    self.instantiate_template_at_canvas_center(instances);
}

// canvas drag release
if primary_released && pointer_over_canvas {
    if let Some(instances) = state.template_drag.take() {
        instantiate_at_pointer(instances);
    }
}
```

Expected behavior after fix:

- Click template: inserts at canvas center.
- Drag template: inserts where dropped on canvas.
- Releasing outside the canvas does not accidentally drop the loaded template data.
